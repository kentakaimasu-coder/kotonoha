# ADR-007 承認署名基盤
状態: 未決定 / 日付: 2026-11-02
## 背景
SEC-09「ハッシュだけでなく署名または保護された監査記録で真正性を確認」、技術仕様 §13「自己申告の approved=true だけを信用しない」。
## 選択肢
1. Sigstore(OIDC 連携の鍵なし署名 + 透明性ログ)
2. 組織の鍵(minisign / SSH 署名)で承認記録に署名し、公開鍵をリポジトリ外で管理
3. 保護された監査サービス(承認 API)に記録し、ロックはその記録 ID を参照
## 推奨
2 を MVP、3 を製品版。検証器は `kotonoha_lock::ApprovalVerifier` を実装して差し替える。
## 現状(暫定運用)
承認記録は `record_hash` で改ざんを検出するだけ。既定の検証器 `LocalUnsigned` は常に「未検証」を返し、**承認済み解釈を含むプロジェクトの `--locked` ビルドは APP001 で拒否する**(承認を含まないプロジェクトは `--locked` ビルド可能)。
