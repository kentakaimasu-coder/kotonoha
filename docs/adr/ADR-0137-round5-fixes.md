# ADR-0137 第 5 回評価で見つかった点の修正(名前の変更・まとめて消す・空でもよい項目・条件付きボタンほか)
状態: 提案(実装) / 日付: 2026-11-15 / 関連: 第 5 回ペルソナ評価([results_round5.md](../evaluation/persona/results_round5.md))、ADR-0135(Studio)、ADR-0134

## 背景
第 5 回(非エンジニア 30 人、Studio あり)で、Studio を使った人の C の SUS(63.7)が使わなかった人(66.4)より低かった。
多かったつまずき: ひな形の要らない部分を消せない(16 人)、日本語の欄で動作を作れない(15 人)、前の結果のメッセージが残る(12 人)、
フォームの見出しが「〜ID」(11 人)、空でもよい項目にできない(10 人)、使えない画面もメニューに出る(9 人)、`金額<JPY>` の記号(17 人)、
定員 0 の失敗が「人数不正」(14 人)、名前を変えられない(4 人)。

## 決定(提案)
1. **名前を変える**: `koto rename 枠 イベント` / `koto rename 枠.定員 上限`、Studio の `「枠」を「レッスン」に変える` / `レッスンの「定員」を「上限」に変える`。
   宣言の名前は部分一致ですべて(枠ID・枠一覧も)、項目の名前は前後の助詞・記号で区切りを見て変える。初期データ(seed*.json)のキーもそろえる。
   変えた後に検査し、**誤りが増えるなら元に戻す**
2. **データをまとめて消す**(Studio `予約を消す`): そのデータを使う動作・確かめる(繰り返し広げる)、画面と約束の行、役割の権限、
   ほかのデータの `予約ID` 項目、それだけが使っていた列挙を消す。語の区切りを見るので「予約数」「予約失敗」は巻き込まない。
   動作を消したときは、それを呼ぶボタン・フォームの行と `動作.名前` の権限も消す。**取り消しは 1 回の指示単位**(複数のファイルをまとめて戻す)
3. **空でもよい項目**: `メモ: 文字列(任意)`(`選択<文字列>` と同じ)、Studio `「メモ」を空でもよいにする`(登録の動作の引数もそろえる)
4. **項目を足すと登録の動作もそろう**(Studio): 名前付きで登録している動作に引数を足し、確かめるの呼び出しに型に合った値を足す。ボタンで呼ぶ動作は触らない
5. **日本語の欄で動作を作る**: `予約を登録できるようにしたい`(本人・「…日時」・状況は自動、ほかは入力。選んでいる画面にフォーム)、
   `「呼び出す」で整理券の状態を「呼出中」にする`、`「来店」で予約の人数を1増やす`(詳細画面にボタン)、`動作「受け付ける」を作る(枠ID、人数)`、
   `予約失敗に「受付終了」を追加`。自動で作る失敗の列挙は、処理に書いた `失敗("…")` の値から作る
6. **状態によってボタンを出す**: `貸出の状態が貸出中のとき「返す」を押すと 返す(貸出.ID)`(`…でないとき` も。Web のみ。K-39)
7. Web の画面: フォームの見出しは参照先のデータ名(「部屋ID」→「部屋」)、新しい結果が出たら前のメッセージを消す、結果に内部の ID を出さない、
   フォーム・ボタンだけの画面は使える人にだけメニューに出す
8. `金額` だけで日本円(`金額<JPY>` の略記)。ひな形の失敗に `定員不正`。ひな形に権限の名前の対応(読取 = read …)と `koto rename` の案内
9. `koto dev`: 開発用データベースを今のデータの形に合わせられないときは、止まらずに古いデータを `data.sqlite.前の形` に退避して作り直す
10. 名前付き引数の誤りのあとに「0 個渡されています」という的外れな誤りが続かないようにする。数字で始まる名前は理由を示して断る(Studio)

## 限界
- 項目名の変更は、助詞・記号で区切りを推測する(文の中で項目名の直後に別の語が続く書き方では変わらないことがある。検査で誤りが増えれば戻す)
- まとめて消すのは、ソースの中の参照を語の区切りで探す(拡張の実装ファイル・分析の SQL の中は見ない)
