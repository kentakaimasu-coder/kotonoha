# ADR-0126 役割(ロール)と全件閲覧の許可
状態: 提案(実装) / 日付: 2026-11-08 / 関連: NR-01, ADR-0118, ペルソナ評価(docs/evaluation/persona/)

## 背景
ペルソナ評価で、居酒屋(客と厨房)・保育園(保護者と先生)・取り寄せ受付(店員同士)など、
「本人の分だけ見える人」と「全員分を扱う人」が同じアプリにいる場面を書けない、という声が続いた。

## 決定(提案)
1. 許可 `全件閲覧.データ名`: 「本人のものだけ閲覧可」のデータでも、この許可を持つ主体には全員の行を見せ、更新も本人の行に限定しない。
   本人限定データを対象にする分析も、この許可を持つ人だけに公開する(以前は TGT001)
2. `役割` 宣言:
   ```kotonoha
   役割 厨房:
       権限 = [注文.読取, 注文.更新, 全件閲覧.注文]
   ```
   - 権限は `データ.読取/作成/更新/削除`(英語の read 等も可)・`動作.動作名`・`全件閲覧.データ`・`実験.結果`
   - 参照先の存在を検査し(REF001)、API 契約の表記に正規化して VAG(`roles`)と api.json に記録する(グラフハッシュに含まれる)
   - backend はトークンの `roles` クレームの役割名から権限を導く。環境変数 KOTONOHA_ROLE_MAP があればそちらを優先(運用で上書き可)
   - 開発用ログインに「<役割>として入る」、`koto token --role <役割>`、`koto safety` に役割の一覧
3. 役割はクライアントの表示の出し分けには使わない(認可は backend だけ: 不変ルール 4)
