# ADR-0135 画面で作る KOTONOHA Studio(日本語の指示・機種ごとの見た目の確認)
状態: 提案(実装) / 日付: 2026-11-09 / 関連: ADR-0130、ADR-0131、ADR-0134、要件「日本人の使いやすさ」

## 背景
文を書くこと自体は日本語になったが、ファイルを開いて書く・ターミナルで動かす、が非エンジニアには最初の壁として残る。
利用者から「GUI でも作れる」「細かい指示は日本語で伝えられる」「Android の機種と iPhone の各種類での表示を画面上で簡単に確かめられる」ことを求められた。

## 決定(提案)
1. `koto studio [--port 4000]` でブラウザの画面を開く(Node のローカルサーバー。127.0.0.1 だけで待ち受ける)
2. **ソースが正**。画面での操作(データ・項目・列挙・画面・動作・役割と権限・約束・確かめる・行の削除・テーマ色)は、すべてソースの行の追加・書き換えとして行い、
   `koto outline`(新設: 構成・検査結果・書ける文の JSON)で検査し直して表示する。「取り消す」で 1 つ前のソースに戻せる。ソースをじかに直すこともできる
3. **日本語の指示**: 決まった言い方(データを作る・項目を追加する・列挙/画面を作る・色を変える)は操作に、それ以外の文は
   約束・確かめる・選んでいる画面に入れる。**入れた行をコンパイラが読めなければ元に戻し**、エラーのヒントと、書ける文のうち文字の並びが近いものを
   「近い書き方」として押せる形で返す。AI は使わない(解釈の判断はコンパイラだけ。不変ルール 2)
4. **見た目の確認**: `koto dev` を裏で動かし(保存で自動作り直し)、iPhone SE / 15 / 15 Pro Max、Galaxy S24 / A55、Pixel 8、iPad mini、パソコンの
   画面の大きさ(CSS ピクセル)で、生成したアプリを機種の枠に入れて並べる。同じ種類の機種は同じ縮尺で、時刻・電池の帯の下にページを出す
5. 安全: Host の確認(DNS リバインディング対策)、書き込みには起動ごとの合言葉ヘッダと JSON を求める(他のサイトから操作させない)、
   書けるのはプロジェクトの中の .koto と kotonoha.json だけ、古い画面からの行の消去は行の中身が一致するときだけ。
   生成アプリの `frame-ancestors` は、開発用ログインが有効で Studio が起動したときだけ Studio の origin を許す(本番は従来どおり 'none')

## 限界・未決
- 見た目の確認は Web 版を各機種の画面の大きさで表示する。ネイティブ版(SwiftUI / Compose)の画面は、シミュレータ・エミュレータが無い環境では出せない
  (iOS / Android の実機向けビルドは CI で確かめる)。手元にシミュレータがあれば起動する機能は未実装
- 動作の処理の行の並べ替え、画面の文の並べ替えは「ソース」で行う
- 日本語の指示の言い換えの幅は決まった言い方の範囲。手元のオープンモデル(ADR-0127)で候補を出す連携は未実装
