# ADR-0136 計算項目と、集計・ログインした人との結びつけ
状態: 提案(実装) / 日付: 2026-11-15 / 関連: 第 4 回ペルソナ評価(results_round4.md §4)、ADR-0128

## 背景
第 4 回で、一覧に計算した値(残席 = 定員 − 予約数)を出せない、集計の単位が ID のまま、ログインした人とスタッフのデータを結びつける書き方が分からない、という声があった(E21・E25・E11・E26)。

## 決定(提案)
1. **計算項目**: データの中に `残席 = 定員 - 予約数` と書く(保存する項目は `名前: 型`、計算項目は `名前 = 式`)
   - 式に使えるのは同じデータの整数・金額の項目、整数、`+ - *` と括弧。型は整数(金額を含めば金額)。空でもよい項目は使えない
   - 読むときに計算する(SELECT に `("定員" - "予約数") AS "残席"` を足す)。保存しないので、ずれない
   - 一覧・詳細の表示、`…の多い順に一覧表示` の並べ替え、動作の中での読み取り(`枠.残席 >= 人数`)、「確かめる」の `枠(s1)の残席は 3` に使える
   - 書き換え(`枠.残席 = 0`)は理由を示すエラー。絞り込みには使えない(項目がないと出る)。動作の中で元の項目を書き換えても、同じ動作の中では読んだときの値のまま
2. **集計の単位が「データ名ID」なら、Web の画面ではそのデータの名前で出す**(そのデータの一覧 API を用意する)
3. **ログインした人との結びつけ**は新しい構文を足さず、書き方を示す: スタッフの ID をログインの名前にする → `スタッフを取得(本人)`、
   引数 `スタッフID` は名前で選ぶ欄、約束 `割当はスタッフIDが本人のものだけ閲覧可`(チュートリアルの表)

## 限界
- iOS / Android の生成画面には計算項目を出していない(API の応答には入る)
