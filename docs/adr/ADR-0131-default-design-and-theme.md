# ADR-0131 生成する Web 画面の既定デザインとテーマ色
状態: 提案(実装) / 日付: 2026-11-09 / 関連: FR-015(デザイントークン)、ADR-0130、SEC-05(CSP)

## 背景
生成される Web 画面は「読みやすさとコントラストの最低限」の 30 行の CSS だけで、素の HTML の表と青い下線リンクに近かった
(docs/design/before-list.png)。業務で使う画面として見た目が弱く、利用者の信頼感・使い心地を損ねていた。
ペルソナ評価もこれまで機能と書きやすさだけを見ており、見た目を評価していなかった。

## 決定(提案)
1. **既定のテーマを作り直す**(runtime/web/app.css)。色・余白・角丸はすべて CSS 変数(トークン)
   - 上の帯: アプリ名の頭文字の印、画面の切り替えは丸いタブ(今の画面を色で示す)、ログイン状態は緑の点
   - 一覧: 角丸のカード状の表、件数の札、数(整数・金額)は右揃え・等幅数字、行全体が押せる(› の印)
   - 詳細: 項目名と値を区切り線で並べたカード
   - 列挙と真偽の値は **状態の札**(完了・承認など=緑、未対応・確認中など=黄、却下・異常など=赤、それ以外は名前から決まる色)。
     色だけに頼らず、札の中に文字がある
   - フォーム: カード、入力欄は 2〜3 列に並ぶ(長い文章の欄は全幅)、見出しに「必須」「任意」、フォーカスは色の輪
   - 結果の知らせ: 成功は緑の帯(✓)、失敗は赤の帯(!)。データが無いときは点線の枠で「データがありません」
   - 権限が無くて操作がすべて隠れた画面には、空白の代わりに案内を出す
   - **狭い画面(640px 以下)では一覧の行をカードにして**、各値の前に項目名を出す(横スクロールしない)
   - OS の設定に合わせて **暗い表示** に切り替わる。動きを減らす設定では動きを止める
   - ログイン・見つからない画面(サーバーが直接返す画面)も同じ見た目にする
2. **テーマ色**: `kotonoha.json` に `"theme": {"color": "緑"}` と書くと、ボタン・タブ・印の色が変わる。
   色の名前(藍・紺・青・緑・深緑・朱・紅・紫・橙・茶・墨。既定は藍)か `#RRGGBB`。
   **ボタンの白い文字とのコントラストが 4.5 未満の明るい色は `koto check` / `koto build` で止める**(APP001。理由と使える名前を表示)
3. CSP(`style-src 'self'`)は変えない。見た目はすべて app.css で決め、style 属性・外部フォントは使わない
4. 見た目の確認は、生成した画面を Playwright で撮影して目で確かめる(docs/design/ に前後の画像)

## 対象外・未決
- iOS / Android は各 OS の標準部品の見た目のまま。テーマ色は反映する(iOS は `.tint`、Android は Material の主色。2026-11-09 追補。
  CI の実機ビルドは examples/izakaya(テーマ色 朱)で確かめる)
- 部品ごとの見た目の指定(例: 一覧をカードの並びで出す)を文で書く方法は未決
- 実在の利用者による見た目の評価は未実施
