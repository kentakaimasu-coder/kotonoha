# ADR-0118 Capability の粒度と行レベル認可
状態: 提案(推奨案で実装済み・承認待ち) / 日付: 2026-11-03
## 問題
仕様 §9 は「呼出グラフ上の必要権限を集約」し、実行時に主体が全 Capability を持つことを要求する。この方式だけでは、購入者が `注文する` を使うために `商品.update` が必要になり、**同じ主体が他の更新系動作(例: 価格変更)も呼べてしまう**。
## 決定(案)と実装
1. **動作単位の許可**: 主体が `動作.{動作名}` を持てば、その動作だけを実行できる(資源 Capability は静的検査と、許可を持たない主体への従来の判定に使う)。資源 Capability をすべて持つ主体も従来どおり実行できる(仕様 §9 との互換)。API 契約の `access.grant` に許可名を出す。
2. **行レベル認可**: 約束 `{データ}は{フィールド}が本人のものだけ閲覧可`(C-OWNER)。そのデータの一覧・詳細・アダプタの取得/一覧/更新/削除は「フィールド = 主体 ID」の行だけを対象にし、登録時は所有者を主体 ID に固定する(他人名義は 403)。所有者の変更は 403。
3. 組込み値 `本人`(ADR-0119)で、動作の中から主体 ID を参照できる。
4. 本人限定データを集計する知識は、集計と行レベル認可の関係が未定義のため生成時に TGT001。
