# ADR-0102 厳密層の追加構文
状態: 提案 / 日付: 2026-11-02 / 関連: C-02, U-10, FR-003
## 決定(案)
| 構文 | 例 | 意味 |
|---|---|---|
| 型の別名 | `型 注文ID = 識別子` | **透過的**(注文ID と 識別子は同一型) |
| 列挙 | `列挙 注文失敗:` + 1 行 1 値 | 名目型。文字列リテラルは期待型が列挙なら値名として解釈 |
| 条件分岐 | `もし 条件:` / `そうでなければ もし 条件:` / `そうでなければ:` | |
| 繰り返し | `繰り返す 項目 から 一覧:` | 一覧/配列の各要素。項目は再代入不可 |
| 否定 | `!条件` | |
| 自動包装 | 戻り型 `結果<T,E>` の動作で `x を返す`(x: T) | `成功(x)` と同じ |
| 失敗の値 | `失敗("数量不正")` | E が列挙ならその値名 |
| 取引 | `取引:`(入れ子不可) | 原子性の実行時意味論は Backend 生成時に定義 |
## 代替案
- 別名を名目型にする(注文ID と 識別子を区別): 型安全は上がるが変換構文が必要。M1 後半で再検討。
- 繰り返しの語順を `一覧 の 各 項目 について:` にする: 自然だが助詞の分割規則が要る(ADR-0101 と衝突)。
## 未決
`失敗` の値に文字列を許すか(現在は E が文字列型なら可)。
