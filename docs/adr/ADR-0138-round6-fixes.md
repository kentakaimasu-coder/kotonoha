# ADR-0138 第 6 回評価で見つかった点の修正(名前の変更の規則・役割だけの画面・Studio の指示の追加)
状態: 提案(実装) / 日付: 2026-11-15 / 関連: 第 6 回ペルソナ評価([results_round6.md](../evaluation/persona/results_round6.md))、ADR-0137

## 背景
第 6 回で、`koto rename` は 30 人中ほぼ全員が使ったが、一緒に変わった名前に気づかず次の rename が失敗した(29 人)、
注釈まで書き換わった(27 人)。Studio では型の変更・役割・項目を消す・列挙の値の名前が日本語で言えず、20 人がソースを書き直した。

## 決定(提案)
1. **名前の変更の規則**(`koto rename` と Studio で同じ)
   - 注釈(# …)の行は変えない
   - 宣言の名前は部分一致で変える(枠ID・枠を追加・枠一覧 も)が、直後がひらがな(助詞を除く)なら変えない(「問い合わせる」は動作の名前のまま)
   - 一緒に変わった名前を表示する。見つからない名前には似た名前を示す
   - 項目の名前は、そのデータに関係する所だけ変える: そのデータの宣言、`v = データを取得(…)` とした v の `v.項目`、`データを登録(項目: …)`、
     そのデータの名前を含む画面・約束・確かめるの文。列挙の値の行と文字列("…")の中は変えない
2. **役割だけの画面**: 画面に `この画面は受付係だけ`(`と` で複数)。Web のメニューには、その役割の権限をすべて持つ人にだけ出す。
   表示だけの出し分けで、データの保護は約束・権限(backend)が行う。iOS / Android はメニューに出す(K-40)
3. **条件付きボタン** `…が返却済みでないとき「…」を押すと …` を読めるようにする(`のとき` を含む形しか探していなかった)
4. **確かめる**: 同じ確かめるの中で `坂本(配車係)` と書いた人は、後の行で `坂本` とだけ書いても同じ役割にする
5. **ひな形の確かめる**は、最初の行で確かめる用の枠・品目を作って名前を付けて使う(初期データを入れ替えても ✗ にならない)
6. **koto dev**: seed.json が前に入れたときと変わっていたら、開発用のデータを作り直す(古いデータは `data.sqlite.前の初期データ` に残す)
7. **Studio の日本語の指示**: 権限を与える(`受付係に予約の更新を許可する` / `受付係は予約を更新できる` / `店長に動作「締める」を許可する`)、
   役割を作る(`役割「店長」を作る(…)`)、型を変える(`予約の「状態」を「予約状態」にする`。同じ型なら名前の変更)、項目を消す(`予約のメモを消す` / `メモを消す`)、
   列挙の値の名前(`列挙「状況」の「受付」を「受付中」に変える`)、アプリの名前(`アプリの名前を「料理教室」にする`)、動作の入力を空でもよい欄に。
   項目を足すとき、名前の合う列挙(「状態」→「予約状態」)を型にする。失敗しない動作は失敗の列挙を作らず結果も返さない形にする。
   データをまとめて消すとき、消す動作の失敗の種類以外の列挙は残す。消した確かめるの古い結果は出さない。
   読めない文で画面の文らしくないものは「どの画面?」と聞かず、言える言い方を示す
8. ひな形に、アプリの名前が画面のいちばん上に出ることを書く

## 限界
- 項目名の変更は、動作の引数の名前(`名前: 文字列`)は変えない(項目名と引数名がずれても動く)
- 役割だけの画面の判定は「その役割の権限をすべて持つか」で行う(権限が包含関係にある別の役割にも出る)
