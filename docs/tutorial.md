# KOTONOHA はじめてのアプリ(チュートリアル)

この文書では、商品を一覧表示して注文できる小さなお店アプリを作り、Web とバックエンドを実際に動かします。
所要時間は 20 分ほどです。

## まずは 3 ステップ(5 分)
プログラミングに慣れていなくても、ひな形から始めれば動くアプリがすぐできます。
```bash
koto init 教室予約 --template 予約受付     # ひな形: 予約受付 / 在庫管理 / 問い合わせ / 日報(koto init --template で一覧)
koto -C 教室予約 dev                       # 検査・生成・初期データ投入・起動を 1 回で行う
# → 表示された http://127.0.0.1:3000/ をブラウザで開く。右上「ログイン」→「名前を入れてすぐ入る」
```
あとは `教室予約/src/app.koto` の名前や項目を自分の用途に書き換えて、もう一度 `koto dev` するだけです。
- 書き方に迷ったら `koto patterns`(自分のデータ名で、書ける文の一覧が出ます)
- 書いた文が通らないときは、エラーの「近い書き方」に正しい書き方が出ます
- 何が自動で守られているかは `koto safety`
- 初期データは `seed.json` に書きます(`koto dev` のたびに入ります。同じ ID は飛ばします)

### よく使う書き方(つまずきやすい所)
| やりたいこと | 書き方 |
|---|---|
| 列挙(選択肢)の値を入れる | 文字列で書く: `件.状況 = "完了"`(**`=` は入れるとき**。`状況.完了` や `完了` ではない) |
| 比べる(確認・もし) | **`==`** を使う: `件.状況 == "完了" を確認 または 失敗("未完了")`、`もし 数 == 0:`。違うは `!=` |
| はい / いいえ の項目 | 型は `真偽`、値は `真` / `偽`。例: `品.提供中 = 偽` |
| 金額の数字 | そのまま数字で書ける: `価格 > 0`、`3000 を返す`(金額は円) |
| まだ値が無いかもしれない項目 | `選択<識別子>` のように `選択<…>` で包む |
| ログインした人だけ見られる | 約束に `回覧はログインした人だけ閲覧可` |
| 本人の分だけ見られる | 約束に `予約は予約者が本人のものだけ閲覧可` |
| 本人の分だけ…でも管理者・厨房は全員分 | 上に加えて、その人に許可 `全件閲覧.予約` を与える(`koto dev` の「管理者として入る」、`koto token --admin`) |
| 客・厨房・先生など役割ごとに権限を決める | `役割 厨房:` の下に `権限 = [注文.読取, 注文.更新, 全件閲覧.注文]`。`koto dev` のログインに「厨房として入る」が出る |
| 役割ごとにボタンを出し分ける | 何も書かなくてよい。ログイン中の人が使えない操作のボタンとフォームは Web では表示しない(認可そのものは backend) |
| 一覧に関連データの名前を出す(ID ではなく) | 項目名を `データ名ID`(例: `イベントID: 識別子`)にする。Web ではイベントの名前で表示される(そのデータの一覧画面があるとき) |
| 詳細画面のフォームで、見ている物の ID を自動で入れる | 動作の引数名を `データ名ID`(例: `備品ID`)にする |
| 二重登録を防ぐ(同じ人が同じ回に 2 回申し込めない) | 約束に `予約は枠IDと予約者の組で重複不可`。2 回目は「既に登録されています」になる。取消した分を数えないなら末尾に `(状態が取消のものを除く)` |
| 状態の順番を守らせる(受付 → 製作中 → 出荷済) | 約束に `注文の状態は 受付 → 製作中 → 出荷済 の順`。飛ばす・戻すと理由と次の状態が日本語で出る。どこからでも取消できるなら末尾に `(取消はいつでも)` |
| 期限・延滞などの日付の計算 | `今日()`、`日後(貸出日, 14)`、`日前(…, 3)`、`日数差(返却期限, 今日())`(延滞日数) |
| フォームの送信ボタンの文言を変える | `予約するのフォームを「申し込む」ボタンで表示` |
| フォームで他のデータから選ぶ(担当者をスタッフから) | 動作の引数名を `データ名ID`(例: `スタッフID`)にする。Web ではスタッフの一覧から名前で選べる |
| 条件を入れて集計を見る(期間の売上など) | 引数のある分析も `期間売上を表示` と書ける。画面に条件の入力欄と「表示」ボタンが出る |
| 複数行の入力欄 | 引数名を「内容・備考・メモ・詳細・本文・説明・感想・コメント・相談・要望・理由」で終わる名前にする(Web) |
| 他の人のデータを操作しようとしたら | 「本人のものだけ閲覧可」のデータは、他の人の分は「見つかりません(無いか、ほかの人のものです)」(404)になる(存在すること自体を知らせないため。自分で書いた失敗より先に効く) |
| 一覧を並べ替える | `注文を注文日時の新しい順に一覧表示`(「の新しい / 大きい / 多い」は降順、`注文を数量順に一覧表示` は昇順) |
| 一覧を絞り込む(未完了だけ・今日の分だけ・自分の担当だけ) | `注文のうち状態が調理中のものを一覧表示`、`…のうち状態が完了でないものを…`、`…のうち注文日時が今日のものを…`、`…のうち担当者が本人のものを…`、期限切れは `…のうち返却期限が今日より前のものを…`。条件は `かつ` でつなげる。並べ替えと一緒に: `注文のうち状態が調理中のものを注文日時順に一覧表示` |
| 集計する(SQL を書かずに) | `注文を品名ごとに集計`(件数と、整数・金額の項目の合計)、`注文を注文日時の日ごとに集計`(`の月ごと` も)、`注文の数量と金額を卓ごとに合計`、絞り込み付き: `注文のうち状態が提供済みのものの金額を品名ごとに合計` |
| API を curl で試す | `koto token --sub 花子` で作ったトークンを `Authorization: Bearer …` に付ける |

以下では、ひな形を使わずに一から作る流れを説明します。

## 0. 準備
- Rust(`cargo`)と Node.js 22.18 以上
- KOTONOHA のコンパイラ `koto` をビルドします

```bash
cargo build --release
export PATH="$PWD/target/release:$PATH"
koto doctor          # 実装状況を表示
```

## 1. プロジェクトを作る
```bash
koto init お店 --name お店
cd お店
koto check           # 「検査に合格しました」と出れば OK
```

`src/app.koto` が KOTONOHA のソースです。日本語と最小限の記号で書きます。

## 2. データを決める
```kotonoha
アプリ「お店」

データ 商品:
    ID: 識別子
    名前: 文字列
    価格: 金額<JPY>
    在庫: 整数
```
- インデントは**半角空白 4 個**です(タブは使えません)
- `:` `=` `(` などの記号は**半角**です。全角で書いてしまったら `koto fmt --zenkaku` でまとめて直せます

## 3. 画面を書く(日本語の文で書く)
```kotonoha
画面 商品一覧:
    商品を一覧表示
    商品を選ぶと 商品詳細 へ

画面 商品詳細:
    商品の名前と価格と在庫を表示
    「購入」を押すと 注文する(商品.ID, 1)
```
画面の文は、決まった**文型**で書きます(一覧表・詳細・ボタン・フォーム・遷移など。`docs/spec/intent_patterns.md`)。
文型に当てはまらない文は、コンパイラが推測せずに**質問**を返します:

```
src/app.koto:9:5: エラー[AMB001] 「人気商品を表示」を解釈できません
    ヒント: 質問: 「人気商品」は知識・データとして定義されていません。何を表示しますか
```

## 4. 処理を書く(厳密に書く)
お金や在庫のように間違えてはいけない処理は `厳密:` の中に書きます。

```kotonoha
型 注文ID = 識別子

列挙 注文失敗:
    数量不正
    在庫不足

データ 注文:
    ID: 注文ID
    商品ID: 識別子
    数量: 整数
    注文者: 識別子

アダプタ 商品をIDで取得(ID: 識別子) -> 商品:
    操作 = 取得(商品)

アダプタ 注文を登録(商品ID: 識別子, 数量: 整数, 注文者: 識別子) -> 注文ID:
    操作 = 登録(注文)

動作 注文する(商品ID: 識別子, 数量: 整数) -> 結果<注文ID, 注文失敗>:
    必要 = [注文.作成, 商品.読取, 商品.更新]
    厳密:
        数量 > 0 を確認 または 失敗("数量不正")
        取引:
            商品 = 商品をIDで取得(商品ID)
            商品.在庫 >= 数量 を確認 または 失敗("在庫不足")
            商品.在庫 = 商品.在庫 - 数量
            注文ID = 注文を登録(商品ID, 数量, 本人)
            注文ID を返す
```
- `必要 = [...]` に、その処理が使う権限を書きます。書き忘れると SEC002 で止まります(**既定ですべて禁止**)
- `取引:` の中は全部成功するか、全部取り消されるかのどちらかです(在庫だけ減って注文が無い、は起きません)
- `本人` はログインしている人の ID です

## 5. 誰が見てよいかを書く(約束)
```kotonoha
約束:
    商品は誰でも閲覧可
    注文は注文者が本人のものだけ閲覧可
```

## 6. 検査して、生成して、動かす
```bash
koto check
koto build --target backend --out ../out/backend
koto build --target web --out ../out/web

# バックエンド(秘密は環境変数で渡す。ソースや生成物には入れない)
cd ../out/backend
export KOTONOHA_JWT_SECRET=$(openssl rand -hex 32)
npm start                                   # http://127.0.0.1:8787

# Web(別の端末で)
cd ../out/web && npm install && npm run build
KOTONOHA_BACKEND_URL=http://127.0.0.1:8787 npm start   # http://127.0.0.1:3000
```
### 6.1 初期データを入れる
```bash
cd ../out/backend
npm run seed -- seed.json      # {"商品": [{"ID": "P01", "名前": "緑茶", ...}]} の形。同じ ID は飛ばすので何度実行してもよい
```

### 6.2 画面を開く・ログインする
- 画面の URL は `http://127.0.0.1:3000/s/画面名`(入力のある画面は `/s/画面名/ID`)。`/` を開くと最初の画面へ移ります
- 開発中のログインは、`npm run token -- --sub 山田 --caps 注文.作成,商品.読取` で作ったトークンを `/login` に貼り付けます。
  権限はソースと同じ日本語(`注文.作成`)でも、API 契約の英語(`注文.create`)でも書けます。動作ごとの許可は `動作.注文する`
- `npm run token -- --help` で使い方を表示します

### 6.3 API をプログラムから呼ぶ
画面のサーバー(3000 番)は API も中継するので、**1 つのポートで画面も API も使えます**。
```bash
curl -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"商品ID": "P01", "数量": 1}' "http://127.0.0.1:3000/api/actions/$(node -e 'console.log(encodeURIComponent("注文する"))')"
```
日時は ISO 8601 の日本時間(`…+09:00`。環境変数 KOTONOHA_APP_TZ で変更可)で返ります。画面でも日本時間で表示されます。

本番では OIDC(社内の認証基盤)でログインします(`KOTONOHA_OIDC_ISSUER` など。docs/architecture.md)。

## 7. 困ったとき
| やりたいこと | コマンド |
|---|---|
| エラーの意味と直し方を見る | `koto explain AMB001` |
| 全角の記号をまとめて半角にする | `koto fmt --zenkaku` |
| 変更がどこに影響するか調べる | `koto impact 商品` |
| API の権限が正しいか試す | `koto test` |
| iPhone / Android アプリも作る | `koto build --target ios` / `--target android` |

## 8. 本番に出す前に
- `koto approve --write-lock` で意味をロックし、`koto build --locked` でビルドします(ロック後にソースが変わると LOCK001 で止まります)
- バックエンドと Web は `KOTONOHA_ENV=production` で起動します。安全でない設定(弱い秘密、HTTPS でない Cookie、開発用ログイン)だと起動しません

## 9. 言語を広げる: 関数・外部関数・分析・部品・実験
完全な例は `examples/lab` にあります(`koto -C examples/lab check`)。

### 9.1 関数(副作用なし)
```kotonoha
関数 値引き後(価格: 金額<JPY>, 値引き: 金額<JPY>) -> 金額<JPY>:
    もし 値引き > 価格:
        価格 - 価格 を返す
    価格 - 値引き を返す
```
関数の中ではデータの読み書き・`本人`・`現在日時()` は使えません(同じ入力なら必ず同じ結果にするため)。
組込み関数: `長さ` `件数` `絶対値` `最大` `最小` `文字列化` `含む` `現在日時`(動作の中だけ)。

### 9.2 外部関数(TypeScript / Python)
既にある TypeScript のコードや、Python の機械学習モデルを呼べます。
```kotonoha
外部関数 割引額(価格: 金額<JPY>) -> 金額<JPY>:
    実装 = "ext/pricing.ts"

外部関数 需要予測(商品ID: 識別子, 価格: 金額<JPY>) -> 整数:
    実装 = "ml/forecast.py"
```
```python
# ml/forecast.py(関数名は宣言と同じ)
def 需要予測(商品ID: str, 価格: int) -> int:
    return max(0, 120 - 価格 // 250)
```
- 引数と戻り値は API と同じ JSON の値(整数・金額は数値、日時は ISO 8601 の文字列)
- 戻り値は宣言した型で検査されます。違えば 422(`external_type`)
- 実装ファイルの中身を変えるとグラフのハッシュが変わり、本番ビルド(`--locked`)は承認し直すまで止まります
- Python は backend の起動ユーザーの `python3`(`KOTONOHA_PYTHON` で変更可)。必要なパッケージは各自の環境に入れてください

### 9.3 分析(SQL)
```kotonoha
分析 商品別売上() -> 一覧<記録{商品ID: 識別子, 売上: 金額<JPY>, 件数: 整数}>:
    対象 = [注文]
    SQL = "analytics/sales_by_product.sql"
```
```sql
SELECT "商品ID" AS "商品ID", SUM("金額") AS "売上", COUNT(*) AS "件数"
FROM "注文" GROUP BY "商品ID" ORDER BY "売上" DESC
```
- 書けるのは SELECT 1 文だけ。読める表は `対象` に書いたデータだけ。引数は `:開始` のように書きます
- 画面に `商品別売上を表示` と書くと表になります。API は `GET /api/analyses/商品別売上`
- 列名は戻り値の記録の名前と同じにします(`AS "売上"`)

### 9.4 部品(手書きの UI)
```kotonoha
部品 星評価(評価: 整数):
    web = "ext/StarRating.ts"
    ios = "ext/StarRating.swift"
    android = "ext/StarRating.kt"

画面 商品詳細:
    星評価(商品.評価)を表示
```
- Web は `React.createElement` で書きます(JSX は使えません)。関数名は部品名と同じにします
- 実装の無いターゲットでその部品を使うと、そのターゲットの生成が TGT001 で止まります

### 9.5 実験(A/B テスト)
```kotonoha
実験 購入ボタン文言:
    画面 = 商品詳細
    変種 = [購入, 今すぐ購入]     # 先頭が今の表示(対照群)
    割合 = [50, 50]
    成果 = 購入する               # この動作が成功したら成果
```
- 同じ端末には常に同じ変種が出ます(Web は Cookie、スマホは端末内の ID)
- 結果は `GET /api/experiments/購入ボタン文言/results`(許可 `実験.結果` が必要)。変種ごとの表示数・成果数・成果率と p 値が返ります
- 途中で何度も結果を見て、良さそうなところで止めると誤った結論になりやすくなります。先に「何人に見せたら判断するか」を決めてください

## 10. 手元の AI に解釈を手伝わせ、使うほど育てる

`@柔軟` の画面に決まった文型でない文(例「人気商品を表示」)を書くと、`koto check` は「未承認の曖昧さ」で止まります。
手元のパソコンで動くオープンモデル(例: Ollama の `qwen2.5:7b`)に、解釈の候補を出させることができます。
ソースは機械の外に送りません(接続先は 127.0.0.1 / localhost だけです)。

```sh
ollama pull qwen2.5:7b                      # 初回だけ
koto learn init                             # 学習記録を有効にする(~/.kotonoha/learn)
koto resolve --adapter local --model qwen2.5:7b
koto approve 'screen.人気#…' 1 --approver 花子   # 候補を見て、人が選ぶ
```

- AI の候補は、形式の検査と「既知の文型として成り立つか」の再照合を通ったものだけが出ます。採用するのは常に人です。
- 承認した解釈と選ばなかった候補は学習記録に残り、次からは似た文の例としてモデルに見せるので、使うほど当たりやすくなります。
  同じ文なら `koto resolve --adapter memory` で AI なしでも候補が出ます。
- `koto learn export --out 学習データ` で追加学習用のデータ(SFT / DPO)を書き出せます。追加学習したモデルは
  `koto learn eval --model 新しいモデル --min 0.8` で過去の承認をどれだけ当てられるか測り、基準を満たしたときだけ使ってください。
  `koto learn status` で成績の推移を見られます。
