# Claude Code 実装指示 — KOTONOHA

最初に `01_requirements.md` と `02_technical_spec.md` を読み、要件ID/テストIDを追跡すること。ユーザーが承認していない仕様を確定したと主張しないこと。仕様が不明なら `docs/adr/` に選択肢と推奨案を記録し、ブロッカーを明示すること。

## 実装原則
1. 最初にRust workspace、CI、`koto` CLIを作成する。
2. 各PRは単一のマイルストーンに限定し、ユニット/ゴールデン/負例テストを追加する。
3. 意図のAI解釈は `resolver` アダプタに隔離する。AI出力を直接実行しない。
4. ロックなし・未承認・型不一致・権限不足・ターゲット未対応は必ず失敗させる。
5. P0はWeb/Backendに限定。iOS/Androidは契約インターフェースのみ先行する。
6. ビルド結果と実装済み範囲を毎回報告し、未実装機能を完成扱いしない。

## 最初の依頼
Phase 0として、言語のトークン一覧、AST構造、EBNF完全版、VAG JSON Schema、エラーコード一覧、テストフィクスチャを作り、レビュー可能なADRを提出。その後にLexer/Parserを実装。MVPゴールは「売れ筋商品を表示」の30日・売上金額・20件の意味確定と、商品一覧Web+Backend CRUDの垂直スライス。
