## NR-01 日本人のユーザーにとっての使いやすさ
- コンパイラの診断・ヒント・CLI ヘルプ・生成アプリの画面文言はすべて日本語(既存)
- 診断に該当行の抜粋と位置の印を表示する。`koto explain <コード>` でエラーの意味と直し方を日本語で説明する
- 全角記号の自動同一視はしない(技術仕様 §3.2)。代わりに `koto fmt --zenkaku` で、利用者の明示的な操作として全角英数記号を半角に直せる
- 生成 Web のフォームは IME 変換確定の Enter で誤送信しない。数値欄の全角数字・全角マイナスを受け付ける(Web / iOS / Android)
- 金額は円表記、日時は日本の表記(既定 Asia/Tokyo)
- 日本語のチュートリアル(docs/tutorial.md)
- iOS / Android の生成アプリの開発言語(既定ロケール)は日本語

## NR-02 セキュリティの強化
- 応答に技術の痕跡(製品名・バージョン・フレームワーク名)を出さない(NR-03 と共通)
- セキュリティヘッダ: API は `Content-Security-Policy: default-src 'none'`、`Cross-Origin-Resource-Policy: same-origin`、`Referrer-Policy: no-referrer`。Web は CSP・COOP・CORP・Permissions-Policy、本番では HSTS
- 認証失敗(401)が続く接続元を一時的に遮断する(トークン総当たり対策)
- 遅いリクエストによる枯渇攻撃(slowloris)対策としてヘッダ・本文の受信時間に上限
- 本番モード(`KOTONOHA_ENV=production`)では安全でない設定(開発用ログイン、Secure でない Cookie、弱い秘密)で起動しない
- 監査ログ: 認証失敗・権限不足・レート制限・ログイン・承認を `level: "audit"` で記録
- 承認記録の Ed25519 署名と信頼鍵での検証(ADR-007 の推奨案 2)
- サプライチェーン: 生成物に SBOM(CycloneDX)を同梱。CI で `cargo audit`・`npm audit`・CodeQL
- コンパイラ自身の堅牢性: 任意の入力でパニックしないことを乱数入力テストで確認

## NR-03 「知られていないこと」の扱い
「まだ知られていない」ことは**セキュリティの根拠にしない**(知られた時点で守りが消えるため。Kerckhoffs の原則)。
依頼者の意図(狙われにくく、破られにくい)を、仕組みが公開されても崩れない次の性質に置き換える:
1. **攻撃面の最小化**: backend は SQLite なら npm 依存ゼロ。API は画面が使うものだけを生成する
2. **定番構成への一斉攻撃を受けにくい**: 生成コードは広く使われる Web フレームワークのサーバー実装に依存しない(Node 標準 http のみ)
3. **痕跡を出さない**: ヘッダ・エラー本文・Cookie 名・ヘルスチェックに製品名やバージョンを出さない
4. **知られても安全**: 認証・認可・入力検証・取引は、実装を読まれても破られない設計で、負例テストで確認する
5. 注意: リポジトリ `kentakaimasu-coder/kotonoha` は現在 **public**。非公開であることに価値を置くなら private にする判断が必要(依頼者の操作)

## NR-04 A/B テストと JS 機能の拡張
- 言語に `実験` 宣言を追加する。画面のボタン文言や拡張部品を変種として出し分け、成果(動作の成功)までを計測する
- 割付はサーバー側で決定的(実験名と利用者 ID のハッシュ)。Web は SSR 時に変種を決め、モバイルは同じ API で取得する
- 結果(露出数・成果数・成果率・対照群との差の p 値)を API で取得できる。閲覧には `実験.閲覧` の許可が必要
- 言語に `部品` 宣言を追加し、Web は TypeScript/React、iOS は SwiftUI、Android は Compose の手書き部品を型付きで組み込める(FR-022 の前倒し)。部品のファイルはロックの対象
