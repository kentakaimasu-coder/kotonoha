# 意図文型(有限集合)

状態: 提案(ADR-0111/0112/0123/0125) / 最終更新: 2026-11-07 / 上位文書: 技術仕様書 §3.1, §5, §7 / 実装: `crates/intent`

意図層の 1 行は、以下の文型に**字面で**照合する。形態素解析は使わない。`{データ}` `{画面}` `{動作}` `{知識}` `{フィールド}` は宣言名(知識は別名も可)の完全一致。どれにも一致しない行は AMB001(UNRESOLVED_INTENT)とし、質問をヒントに付ける。

## 1. 画面
| ID | 文型 | VAG ノード | 意味 |
|---|---|---|---|
| P-LIST | `{データ}を一覧表示` | display(ui=list) | D の一覧。D.read |
| P-LIST(並べ替え) | `{データ}を{フィールド}順に一覧表示` / `{データ}を{フィールド}の新しい順に一覧表示` | display(ui=list, order) | 「の新しい/大きい/多い/高い/遅い/降」は降順、「の古い/小さい/少ない/安い/低い/早い/昇」と無指定は昇順(ADR-0128) |
| P-LIST(絞り込み) | `{データ}のうち{条件}(かつ{条件})*のものを一覧表示`(並べ替えと併用可: `…のものを{フィールド}順に一覧表示`) | display(ui=list, filters) | 条件: `{F}が{値}` / `{F}が{値}でない` / `{F}が今日`(日時・日付、アプリの時刻帯) / `{F}が本人`(識別子・文字列)。値は列挙値・真/偽・整数・文字列・日付。行レベル認可の条件は常に併せて適用(ADR-0128) |
| P-FIELDS | `{データ}の{フィールド}(と{フィールド})*を表示` | display(ui=detail) | 画面の入力 D の指定フィールド。D.read |
| P-KNOWLEDGE | `{知識}を表示` | query | 知識の結果一覧。対象データの read |
| P-KNOWLEDGE-N | `{知識}を{N}件表示` | query | 件数だけ N に上書き(1〜10000)。他の意味は変えない(TC-002) |
| P-AGGREGATE | `{データ}を{フィールド}ごとに集計` / `{データ}を{日時}の日ごとに集計`(`の月`)/ `{データ}の{F}(と{F})*を{フィールド}ごとに合計` / 絞り込み付き `{データ}のうち{条件}のものを…ごとに集計`・`{データ}のうち{条件}のものの{F}を…ごとに合計` | query(ui=table, aggregate) | 単位ごとの件数と合計(集計は整数・金額の全フィールド、合計は指定のフィールド)。日・月はアプリの時刻帯。D.read、本人限定データは本人の行だけ(全件閲覧の許可があれば全員)(ADR-0128) |
| P-NAV | `{データ}を選ぶと {画面} へ` | navigation(event=tap) | 同じ画面に P-LIST の D が必要。遷移先の入力が D になる |
| P-FORM(文言付き) | `{動作}のフォームを「申し込む」ボタンで表示` | display(ui=form, submit) | 送信ボタンの文言を変える(ADR-0129) |
| P-FORM | `{動作}のフォームを表示` | display(ui=form, event=submit) | 動作の引数を入力項目にしたフォーム(ADR-0115) |
| P-BUTTON | `「ラベル」を押すと {動作}(引数, …)` | display(ui=button, event=tap) | 引数は厳密層の式。スコープは画面の入力 D(変数名 = データ名)。呼出は不可 |
| P-COMPONENT | `{部品}(引数, …)を表示` | display(ui=component) | 拡張部品(ADR-0123)。引数の規則は P-BUTTON と同じ |
| P-ANALYSIS | `{分析}を表示` | query(ui=table, analysis) | 分析の結果表(ADR-0125)。引数のある分析は条件の入力欄と「表示」ボタン付き(ADR-0129)。対象データの read |

補足:
- P-FIELDS のデータ名は `の` の前の最長一致。フィールドは `と` で分割し、全て存在しなければ全体を 1 フィールド名として試す。
- 画面の入力(ADR-0111): P-NAV で遷移してくる D。異なる D を渡す遷移が混在すれば TYP001。入力が無いのに P-FIELDS を使えば REF001。

## 2. 約束
| ID | 文型 | 意味 |
|---|---|---|
| C-PUBLIC | `{データ}は誰でも閲覧可` | D.read を未認証にも許可 |
| C-OWNER | `{データ}は{フィールド}が本人のものだけ閲覧可` | 行レベル認可(フィールドは 識別子 か 文字列)。ADR-0118 |
| C-UNIQUE | `{データ}は{F}(と{F})*の組で重複不可` / `{データ}は{F}が重複不可` | 一意制約。違反は 409(ADR-0129) |
| C-SEQUENCE | `{データ}の{F}は 値 → 値 → … の順` | 列挙 F は最初の値で作り、同じ値か次の値にしか変えられない。違反は 409(ADR-0129) |
| C-AUTH | `未認証なら{データ}不可` | D への操作に認証を要求(デフォルト拒否のため既定でも同じ。明示の記録として残す) |
同じ D に C-PUBLIC と C-AUTH、または C-PUBLIC と C-OWNER があれば AMB002。

## 3. 動作本体の意図行
MVP では文型を定義しない(常に AMB001)。処理は `厳密:` で書く。

## 4. 曖昧性モードと承認(ADR-0112)
| モード | 文型に一致しない行 |
|---|---|
| `@厳密`(既定) | AMB001。承認記録は**適用しない** |
| `@柔軟(確認)` | 意図 ID と文ハッシュが一致する承認記録があれば、その**正規文**を同じ照合器にかける |
| `@柔軟(自動)` | 文ハッシュが一致する承認記録(他の意図 ID のものでも可)を再利用する |
- 正規文が文型に一致しない、または参照が成立しなければ APP001(AI・人のどちらの出力も直接意味を確定しない)。
- 知識の別名はすべてのモードで使う(承認済みの知識の一部とみなす)。

## 5. 意図 ID
`{所有者}#{SHA-256(文)の先頭12桁}`。所有者は `screen.{名前}` / `action.{名前}` / `contract`。同じ所有者に同じ文が複数あれば `~2` `~3` を付ける。
