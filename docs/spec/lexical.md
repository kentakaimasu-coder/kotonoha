# 字句仕様

状態: 提案(ADR-0101) / 最終更新: 2026-11-02 / 上位文書: 技術仕様書 §3.2 / 実装: `crates/lexer`

## 1. ソース
- UTF-8。不正なバイト列は SYN001。BOM 付きは SYN001(`koto fmt` で除去)。
- **NFC 正規化済みであること**。非 NFC の行は SYN002(`koto fmt` で正規化)。コンパイラは入力を黙って書き換えない(位置情報がずれないため)。
- 改行は LF。CRLF は LF と同一視する(Windows: NFR-009)。単独 CR は SYN001。
- 位置: `line`/`column` は 1 始まり、column は **Unicode スカラー値単位**。`start`/`end` はバイトオフセット。

## 2. 行とインデント
- 1 物理行 = 1 論理行(行継続なし)。
- 先頭の半角空白 4 個 = 1 段。4 の倍数でなければ SYN001。**タブは行のどこでも禁止**(文字列内を除く)。
- 空行・コメントだけの行はインデント計算から除く。
- ブロックは `:` で終わる見出し行の直後に 1 段深くして始まる。見出し以外の直後に深い行があれば SYN001。

## 3. コメント
- 文字列リテラルの外にある `#` から行末まで。

## 4. 禁止文字(文字列リテラルの外)
| 文字 | 診断 |
|---|---|
| タブ U+0009 | SYN001 |
| 全角 ASCII U+FF01〜U+FF5E(`＝` `（` `ＩＤ` 等) | SYN001 + 半角候補のヒント(自動同一視しない) |
| 全角空白 U+3000 | SYN001 |
| その他の制御文字 | SYN001 |
| 厳密層での `、` `。` などの記号 | SYN001(区切りは `,`) |

## 5. トークン(厳密層・宣言見出し)

### 5.1 語(識別子・予約語)
```
word_char = "_" | Unicode Alphabetic | Unicode Numeric   (Rust char::is_alphanumeric)
word      = word_char , { word_char }      (* 先頭が ASCII 数字なら数値リテラル *)
```
- 語は**最長一致**。助詞は自動分割しない: `注文IDを返す` は 1 語、`注文ID を返す` は 識別子 + 予約語。
- 語全体が予約語表に一致したときだけ予約語。`取引先` は識別子、`取引` は予約語。
- 予約語で終わる 1 語(`…を返す` `…を確認`)が単独の文として現れた場合は、空白の入れ忘れとして修正ヒント付き SYN001。

### 5.2 予約語
| 語 | 用途 | 語 | 用途 |
|---|---|---|---|
| アプリ | アプリ宣言 | 厳密 | 厳密ブロック |
| 型 | 型の別名 | 取引 | 取引ブロック |
| 列挙 | 列挙型 | もし / そうでなければ | 条件分岐 |
| データ | データ宣言 | 繰り返す / から | 繰り返し |
| アダプタ | データアダプタ | を確認 / または | 確認文 |
| 知識 | 知識宣言 | 失敗 / 成功 | 結果の構築 |
| 画面 | 画面宣言 | を返す | 返却文 |
| 動作 | 動作宣言 | 真 / 偽 | 真偽リテラル |
| 約束 | 約束宣言 | なし | 選択の空 |
| 必要 / 効果 / 操作 | 宣言内のキー | 記録 | 記録型 |

### 5.3 リテラル
| 種類 | 形 | 例 |
|---|---|---|
| 整数 | ASCII 数字、`_` 区切り可(連続・末尾不可)、i64 範囲外は SYN001 | `0` `1_000` |
| 小数 | 数字 `.` 数字(字面を保持。精度は ADR-0106 未決定) | `3.14` |
| 文字列 | `"…"`(エスケープ `\" \\ \n \t \u{XXXX}`)または `「…」`(エスケープなし・入れ子なし) | `"在庫不足"` `「購入」` |
| 真偽 | `真` `偽` | |
| 空 | `なし` | |
- 数値の直後に語文字が続くと SYN001(`5件` は意図層でのみ書ける)。

### 5.4 記号
```
( ) [ ] { } , : . -> = == != < <= > >= + - * / && || ! @
```
`!` と `@` は仕様書 §3.2 に無い追加(否定・注釈)。

## 6. 意図層の行
画面本体・約束本体・動作本体の意図行・知識の値は**トークン化せず生テキスト**として保持する(コメント除去・前後空白除去のみ)。意味付けは [intent_patterns.md](intent_patterns.md) と [knowledge.md](knowledge.md) の有限文型で行う。
