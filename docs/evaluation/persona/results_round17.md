## 0. 第 16 回からの変更点
「先生にすべてのデータの登録を許可する」、担当者は登録した本人、「予約するときに回数券を1減らす」、登録の動作でほかのデータを指す値の存在を確かめる、
集計のフォームで行を動かさない、名前の変更でアプリの名前の行を変えない・二重にしない、ほか([results_round16.md](results_round16.md) の 3.)

### 評価の進め方
- **30 人とも同じ版**で行った。評価中に入れた修正(下の 3.)は別の場所で作って確かめ、評価の版は作り直していない。30 人の report.json はすべて読めた(Q10 は引用符の誤りを直して読んだ)
- 1 人(N11)の Studio で「アプリを開く」が別の人のアプリを開いた。止めている間にほかのプロセスが同じポートを使い始めたため(下の 3. で修正)

## 4. 300% 基準に対する判定
- **本人の見積もり: 平均 3.42 倍・中央 3 倍(3 倍以上 26 人)。** 平均は 10 回続けて 3 倍を超えた(第 8〜17 回: 3.08・3.35・3.45・3.22・3.68・3.62・3.53・3.10・3.47・3.42)
- **SUS: 未達(2.51 倍)。** 68.3 点は第 13 回以降で最も低い。「すぐ覚えられる」「自信を持って使える」が下がった
- **行動の指標**: コマンド 0 回。A でソースを書いた人 0 人(初めて)
- 判定(利用者と合わせた方法): **本人の見積もりと行動の指標では 3 倍を満たした。主観の SUS は満たしていない。**
  3 倍で止まる理由は、Studio の操作より「決まった言い方を覚える」「公開を自分でできない」に集まっている
