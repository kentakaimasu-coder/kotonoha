# 評価課題: イベント受付アプリ

勉強会・セミナーの受付アプリを作る。**A: KOTONOHA** と **B: 普段の技術** の両方で、同じ仕様を満たすこと。

## 機能
1. イベント一覧(誰でも見られる): 名前・会場・開始日時・参加費(円)・定員・予約数
2. イベント詳細(誰でも見られる)と、予約ボタン「1名で予約」「2名で予約」
3. 予約: ログインした人だけ。人数が 1 以上でなければ失敗「人数不正」。残席(定員 − 予約数)が足りなければ失敗「満席」。
   成功したら予約数を増やし、予約(イベントID・参加者=ログインした人・人数・予約日時)を記録する。
   **同時に予約が来ても定員を超えないこと**
4. 自分の予約の一覧: **本人の予約だけ**が見える
5. 主催者のイベント登録フォーム(名前・会場・開始日時・参加費・定員。定員は 1 以上)
6. 会場別の集計(会場・イベント数・予約数の合計・定員の合計)
7. 画面は日本語。金額は「¥1,000」、日時は日本時間で表示

## 権限(ログインは JWT)
- `Authorization: Bearer <JWT>`(HS256、秘密は環境変数 `KOTONOHA_JWT_SECRET`)。クレーム `sub`(利用者 ID)・`caps`(権限の配列)・`exp`
- 予約するには `予約.create` と `イベント.read` と `イベント.update`(または `動作.予約する`)
- イベント登録には `イベント.create`(または `動作.イベント登録`)
- 会場別の集計は誰でも見られる(イベントは公開情報のため)
- トークンが無い → 401、権限が足りない → 403、トークンが不正 → 401

## API(採点はこの API と画面で行う)
| メソッド | パス | 応答 |
|---|---|---|
| GET | `/api/data/イベント` | イベントの配列(各要素に ID・名前・会場・開始日時(ISO 8601)・参加費・定員・予約数) |
| GET | `/api/data/イベント/{ID}` | イベント 1 件(無ければ 404) |
| GET | `/api/data/予約` | 本人の予約の配列(ログイン必須。他人の予約は含めない) |
| POST | `/api/actions/予約する` | 本文 `{"イベントID": "...", "人数": 1}`。成功 200 `{"ok": "<予約ID>"}`、業務の失敗 422 `{"error": "failure", "value": "満席" または "人数不正"}`、入力の形が不正 400 |
| POST | `/api/actions/イベント登録` | 本文 `{"名前","会場","開始日時"(ISO 8601),"参加費","定員"}`。成功 200 `{"ok": "<イベントID>"}` |
| GET | `/api/analyses/会場別の予約状況` | `[{"会場","イベント数","予約数","定員"}]` |
| GET | `/api/health` | 200 |

パスの日本語部分は URL エンコードされて届く。

## 画面
- Web の画面(HTML)。イベント一覧に名前などが**エスケープされて**表示されること(名前に `<script>` が入っても実行されない)
- 画面からの予約・登録で、他サイトからの要求(CSRF)を受け付けないこと

## 初期データ(起動前に投入する)
`seed.json` の形式は `{"イベント": [{ "ID", "名前", "会場", "開始日時", "参加費", "定員", "予約数" }]}`
