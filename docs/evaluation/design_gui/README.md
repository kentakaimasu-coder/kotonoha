# デザインの確認と「GUI で簡単に直せるか」の確認

状態: 完了(**AI による画面の評価と、AI が演じるペルソナによるシミュレーション。実在の利用者評価ではない**) / 実施: 2026-11-17〜18
上位文書: [../persona/results_round17.md](../persona/results_round17.md)(同じ時期のペルソナ評価 第 17 回)

利用者の依頼「デザイン性のチェックや、簡単に GUI で修正できるレベルの容易性があるのかのチェック」に応えて、2 つを行った。

## 1. デザインの確認

### 方法
- 課題 A(イベント受付)を Studio の日本語の指示だけで作ったアプリを用意し、Studio と生成アプリの画面を PC 幅(1280px)とスマホ幅(390px)で撮った
  (Studio のホーム・各タブ、アプリの一覧・詳細・ログイン・自分の予約・管理)。スクリプト: [check.cjs](check.cjs)
- **機械で測る指標**: 横のはみ出し、スマホ幅で 40px 未満の押す所、12px 未満の文字、axe(WCAG 2.2 AA)の違反
- **見た目の評価**: 画面写真と指標を、デザインの評価役に読ませ、点数・良い点・直すべき点(重さ・どう直すか)を書かせた: [design_review.md](design_review.md)

### 結果(直す前)
| | 点(10 点満点) | 主な理由 |
|---|---|---|
| Studio | 5 | PC 幅は整っているが、スマホ幅でタブが 1〜2 文字ずつ折り返す・「動かす」タブが横にはみ出す・見た目の端末が白い。「動きの確認」が記号だらけ |
| 生成アプリ | 6 | 一覧・フォーム・ヘッダは整っている。お客さんがいちばん使う詳細の画面に予約のボタンが無く、ピンクの帯が 2 本並ぶ。「データがありません」「送信」など機械の言葉 |

機械で測る指標: はみ出し 0、axe の違反 0、スマホ幅で小さい押す所 30、小さい文字 16(端末の枠の中の時計など)

### 直したこと
| 指摘(重さ) | 直したこと |
|---|---|
| 詳細の画面に予約のボタンが無く、エラー色の帯が並ぶ(高) | ログインしていない人にも主ボタン(押すとログインへ)を出し、下に小さく「ログインすると使えます」。役割が違うときの案内は情報の色に |
| Studio のスマホ幅でタブが折り返す(高) | タブを 1 行の横スクロールに |
| 「動かす」タブが横にはみ出す(高) | 本文とカードの最小幅を 0 にして、表は枠の中でスクロール |
| 見た目の端末が白く、縦に 4 台並ぶ(高) | スマホ幅では 1 台だけ。読み込みを遅らせない |
| 「動きの確認」が記号だらけ(高) | 先頭に「すべて期待どおり(N 件)」の要約、各行は「成功→できる」「失敗("満席")→「満席」で断る」のように言い換え |
| 「データがありません」(中) | 「まだありません」 |
| フォームのボタンが「送信」(中) | 動作の名前(「イベント登録」など) |
| 押す所が 34〜38px(低) | Studio の左の一覧・タブ・ボタン、アプリの一覧のリンクを 44px 以上に |
| 色の選択が変えた後も「(既定: 藍)」(GUI で直す確認から) | 先頭に「今の色: 緑」 |

直した後の機械で測る指標: はみ出し 0、axe の違反 0、**スマホ幅で小さい押す所 0**(直す前 30)、小さい文字 8(端末の枠の中の時計・電池の表示だけ)。
指標の生データ: [objective_before.json](objective_before.json)・[objective_after.json](objective_after.json)

### 残っている指摘(未対応)
- 入力欄の日時が「mm/dd/yyyy」の並びになる(ブラウザの言語による)。ログインの画面にヘッダが無い・説明が長い
- 一覧の見出しの重なり(「イベント一覧」と「イベントの一覧 3件」)、詳細の画面の見出しが画面の種類名(イベント名でない)
- スマホの一覧のカードが縦に長い(項目が全部出る)。Studio の色の選択が「画面で作る」のカードの中にある
- Studio の画面の行に「予約する(イベント.ID, 1)」のような記号が見える(GUI で直す確認でも 10 人中 9 人が挙げた)

## 2. 「GUI で簡単に直せるか」の確認

### 方法
- 1. と同じ、できあがった「イベント受付」アプリを渡し、使っている人からよく来る小さな直し 12 個を、**Studio の画面だけで**上から順に直してもらった: [gui_tasks.md](gui_tasks.md)
  (色・アプリの名前・ボタンの文字・失敗の言葉・並び順・今日以降だけ・項目の追加・ボタンを消す・画面の名前・空でもよい・役割だけのメニュー・最初の画面)
- ペルソナは第 17 回と同じ人から 10 人(N08・N10・N13・N19・N21・N24・N27・N29・Q01・Q06。年齢・IT の得意さが散らばるように選んだ)
- できたかどうかは本人の申告ではなく、できあがったソースと設定を [verify.py](verify.py) で機械的に確かめた。報告: [gui_fix/](gui_fix/)

### 結果
| | 結果 |
|---|---|
| 12 個すべて直せた人(機械で確かめた) | **10 / 10 人** |
| ソースを直接書いた直し | **0 件**(120 件中) |
| 1 個あたりの試した回数 | 平均 1.3 回(最多は 7「持ち物を足して空でもよく」2.3 回、11「主催者だけのメニュー」1.6 回、4「満席の言葉」1.3 回) |
| 「簡単だった」(5 段階) | 全員 4 |
| デザイン(5 段階) | 全員 4 |

- 普段のやり方(作った人・業者に電話やメールで頼む)と比べて、「自分ですぐ直せる」ことを全員が良い点に挙げた
- つまずいた所と対応:
  | つまずき | 人数(報告の文をキーワードで数えた概数) | 対応 |
  |---|---|---|
  | 自分の言い方では通らず、チュートリアルの表の言い方を探してまねた(「主催者だけのメニューにしたい」「最初に出る画面を…」「今日以降」) | 10 | 「…の画面は主催者だけのメニューにしたい」「アプリを開いたときに最初に出る画面を…」を読む |
  | 「アプリを開いたときに最初に出る画面を…」で「アプリの名前に「」は使えません」と出た | 2 | アプリの名前の文と取り違えないようにした |
  | 空の「持ち物」が「未設定」と出る | 9 | 必須で足した項目を空でもよいにしたら、初期データの仮の値「未設定」を消す |
  | 色を変えても色の欄が「(既定: 藍)」のまま | 4 | 先頭に今の色 |
  | 誤りの文に UNRESOLVED_INTENT・P-LIST と英語が出る | 1 | Studio の表示で外し、日本語の案内に置き換える |
  | 「列挙」という言葉が分からない(「満席」の言葉を変える) | 8 | (「「満席」を「定員に達しました」に変える」でそのまま変えられるようにした(第 17 回の前)。左の一覧に列挙が出ない点は残る) |
  | 行の中の記号(「予約する(イベント.ID, 1)」)が怖い | 9 | (残る) |

### 判定
- **小さな直しは、GUI(Studio の画面と日本語の指示)だけで、ソースを書かずにできる水準にある**(10 人全員が 12 個を直せた・ソースは 0 件)
- ただし「自分の言葉で書いて一度で通る」水準にはまだなく、言い方を探す手間が残る。上の対応で 4 つの言い方を足した
